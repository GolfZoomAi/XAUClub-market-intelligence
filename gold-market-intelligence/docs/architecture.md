# Architecture and Phase 2 integration plan

## Phase 1
- `src/lib/demo.ts`: synthetic data ONLY
- `src/lib/bias.ts`: deterministic explainable bias score and data coverage
- `src/components/GoldChart.tsx`: candlestick rendering
- `src/types/market.ts`: typed provider interface, observation and freshness statuses
- `src/app/page.tsx`: responsive dashboard

## Phase 2
1. Verify vendor licensing and live/delayed availability for each instrument before choosing providers.
2. Implement server-side provider adapters and Zod validation; never expose API keys to browser.
3. Normalize source timestamps (UTC) and reception timestamps; display Bangkok local time and source freshness.
4. Introduce caching with provider-specific TTL; FRED real yield is periodic, CFTC COT is weekly, CME OI may not be live.
5. Introduce data-coverage and missing-data safeguards before enabling production bias.
6. Do not treat GC continuous contract prices as identical to XAUUSD spot.
7. Do not scrape TradingView or unauthorized sites.
8. Add tests for stale data, source outages, time-zone conversions and insufficient-data bias.

## Important limitations
Bias weights are illustrative, not backtested or calibrated. Confidence must never be presented as a win probability. The demo summary is static and not generated by an AI service.
